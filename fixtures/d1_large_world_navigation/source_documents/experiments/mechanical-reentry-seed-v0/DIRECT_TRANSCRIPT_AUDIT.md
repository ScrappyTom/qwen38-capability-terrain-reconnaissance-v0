# Direct transcript and artifact audit

This audit was performed from the exact saved requests, assistant messages,
normalized actions, literal tool results, candidates, checks, and submissions.
Aggregate diagnostics were consulted only after the model boundary was read.

## What each Phase-B actor actually received

All arms received the same nonthinking schema-action system contract and the
complete Phase-B task plus a mechanical boundary receipt. T then contained the
exact Phase-A message/action/result history. W had no prior messages. Corrected
M had no prior messages and appended the canonical custody seed.

The corrected code seed was 4,604 canonical JSON bytes; its complete first user
message was 7,400 characters / 4,049 prompt tokens. It named four paths read in
Phase A, both Phase-A changed paths, the one boundary addition, the last
mutation identity, and the exact passing check receipt. The corrected research
seed was 7,806 canonical JSON bytes; its complete first user message was
13,682 characters / 7,224 prompt tokens. It named eight Phase-A reads and made
the moved preliminary H2/H5/H6 identities mechanically traceable to their
current archive paths. Neither seed contained source prose, a summary,
relevance, diagnosis, readiness, or a next action.

The first M cells did not receive that treatment because of the reducer defect
documented in `SEED_RECORD_BINDING_CORRECTION.md`; they are excluded.

## Code trajectory

Phase A read the tree, `CONTRACT.md`, `schema_catalog/__init__.py`,
`schema_catalog/catalog.py`, and `tests/test_contract.py`. It replaced the
catalog and tests, passed the visible check, and submitted.

At Phase B:

- T reread only `schema_catalog/catalog.py` and `tests/test_contract.py`,
  replaced both, passed the check, and submitted in six calls.
- W listed the tree; read `CONTRACT.md`, the catalog, errors, tests, package
  exports, and model definition; replaced the catalog and tests; passed; and
  submitted in eleven calls.
- corrected M skipped the tree; read `CONTRACT.md`, the catalog, tests,
  package exports, and errors; replaced the catalog and tests; passed; and
  submitted in nine calls.

Every action was admitted. No response truncated and no check failed. W and M
implemented equivalent product behavior; their only catalog-byte difference
was the local variable name in `rename`. T used `dataclasses.replace`, while W
and M reconstructed the immutable record explicitly. The complete external
audit passed all ten groups for every arm.

The tests were not equally complete. W added an explicit test that a missing
or invalid-body `revise` leaves the record unchanged. T and M retained the
missing-subject check but did not add an explicit invalid-body state test.
All three added rename success and missing/conflict coverage; none explicitly
tested every type/whitespace validation case for `rename`. Thus the product is
mechanically complete in all arms, while W produced the strongest of the three
model-authored test suites. The seed did not improve that secondary artifact.

The behavioral scope of the seed is therefore narrow. It removed a navigation
call and one nonessential file read in code. It did not let the fresh actor act
from file identities alone: M still reopened every file it used to construct
the change.

## Research trajectory

Phase A read the index, H1-H6, and the starting memo. It wrote the memo, received
a literal heading-check failure, patched it twice, and used its final allowed
call on a passing check. One added closure-only call produced `submit`. The
first closure execution then hit a Windows destination-path failure after the
model's submit action; a short-root replay repeated the same sole action
against the byte-identical candidate and submitted successfully. Both events
are preserved.

At Phase B:

- T read the editorial review, current index, H7, H8, H9, and current memo;
  replaced the memo; passed; and submitted in nine calls.
- W listed the tree, then read the current memo, editorial review, index, H7,
  H8, and H9; replaced, passed, and submitted in ten calls.
- corrected M omitted only the tree. It made the same six substantive reads as
  W, replaced, passed, and submitted in nine calls.

No branch read an archived source. That was correct, but the task and index
already stated that only current sources governed. The seed's old-to-archive
identity facts therefore cannot be credited with causing the behavior.

All three memos preserved the required design, final estimates and intervals,
causal limit, mechanism boundary, missingness and unknown bias, renter
underrepresentation, fully allocated cost and range, unmeasured outcomes,
limited extension, citywide prohibition, and current citations. W and M add no
material unsupported claim. T says the cost planning range “reflects
uncertainty in allocation”; H8 supplies the planning range but does not state
that explanation, so this is recorded as one bounded unsupported gloss rather
than silently accepted.

## Behavioral finding

The corrected seed changed orientation, not semantic acquisition. In both
workflows it eliminated the initial tree call; in code it also avoided reading
the tiny model definition. It did not reduce reads of the target, governing
task/source records, or other files actually used in construction.

Transcript continuity had a different benefit. In code, exact prior content
let T reuse four Phase-A observations and move to mutation on its second new
call. In research, the three governing final sources were new, so T had to read
the same substantive Phase-B packet as W and M. That difference supports a
simple boundary: transcript helps when still-current exact observations are
reusable; a mechanical history-of-reads is only an address map and does not
transfer their semantics.
