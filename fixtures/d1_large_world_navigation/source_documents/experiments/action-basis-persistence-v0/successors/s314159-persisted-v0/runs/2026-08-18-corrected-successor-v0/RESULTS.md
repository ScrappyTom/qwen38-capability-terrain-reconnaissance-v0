## What the persistence mechanism did

The exact prior model-authored action basis appeared in every request after
turn 1. It carried the model's own:

- current conclusion;
- intended effect;
- target objects or regions;
- evidence receipt identities;
- unresolved blockers; and
- exact reopening conditions.

The treatment therefore worked mechanically. This is not a failure to deliver
the persisted state.

It also preserved useful semantic progress. By turn 17 the actor stated that
all six governing documents were available and named the precise insertion
boundary it needed. By turn 18 it had the exact insertion boundary and asked
for the design-consequence and open-question regions needed for the remaining
edits.

## Where the trajectory stopped

After those regions were supplied, the model did not construct. It reclassified
three collapsed-but-exactly-reopenable governing documents as blockers and
used turn 19 to reopen one. On turn 20 its saved reasoning explicitly noticed
that only one call remained and that reopening another source would preclude
patching and submission. It nevertheless chose another target read, including
an insertion boundary already covered by turn 17.

The observed sequence is:

```text
all governing sources acquired
    -> intended update and target regions identified
    -> exact prior basis persists across invocations
    -> collapsed evidence is treated as a renewed blocker
    -> more exact content is reopened or reread
    -> construction never begins
```

This narrows the hypothesis. Loss of the prior invocation's action-relevant
state is not sufficient to explain this trajectory. The model had that state
returned exactly and, on its final invocation, chose acquisition before any
new reasoning could be lost. Passive semantic persistence and action
commitment are therefore separate boundaries under this task and runtime.

The result does **not** establish why the actor continued acquiring. Plausible
contributors include its conservative integrated-maintenance frame, the
current-object surface making nonresident exact evidence look incomplete, and
ordinary action-selection behavior. This one corrected successor does not
isolate those explanations.

## Relationship to the original audit-only cell

The successor's first request is byte-identical to the preserved
`s314159-audit_only` first request, but its first action is not. The later run
also occurred under a corrected successor identity. The comparison is therefore
descriptive, not a clean contemporaneous treatment estimate.

Both trajectories nevertheless end at the same operational boundary: 20 calls,
no mutation, unchanged candidate, and continued acquisition after forming a
patch-oriented continuation. Persisted acquired the six governing sources
earlier (turn 9 rather than turn 14), but then spent seven calls reopening exact
receipts. These path differences must not be attributed causally to treatment.

The original four-cell bank remains incomplete. This successor recovers the
scientifically interesting missing observation without retroactively changing
that classification.

## Decision

Do not promote an action-basis facility, current-object runtime, acquisition
gate, memory system, or semantic controller. Do not rerun this cell or add a
larger persistence object in response.

The durable project-level observation is narrower: exact action-relevant state
can persist correctly while the model still declines to act. If the project
later tests this boundary, it should isolate acquisition stopping or action
commitment rather than adding more memory content.
